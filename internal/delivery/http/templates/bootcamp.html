Bootcamp Fase 1 • Fondasi Bahasa Go & RDBMS

Belajar Golang Dasar, Pointers, Goroutines, hingga Konsep Concurrent & RDBMS

Go (Golang) Railway RDBMS / SQL

Belajar Golang dasar mulai dari installasi, memahami variable, const dan tipe data pada GO programming, hingga konsep concurrent bahasa GO dan eksplorasi relational database (RDBMS).

Modul 1 • Function & Packages Syntax & Scope

Organisasi Package, Exported Identifier & Error Return

Go menggunakan kapitalisasi huruf untuk menentukan visibility: huruf depan kapital (CalculateFee) bersifat publik (exported), sedangkan huruf kecil (parseCents) bersifat privat di package lokal. Fungsi mendukung multiple return value untuk mengembalikan error secara eksplisit.

Modul 2 • Pointers, Struct & Methods Memory Reference

Pointer Receiver vs Value Receiver & Interface Duck Typing

Pahami kapan menggunakan pointer (*User) agar mutasi state tidak membuat salinan memori baru. Interface di Go diimplementasikan secara implisit tanpa keyword implements, memungkinkan dependensi yang longgar dan mudah diuji dengan mock.

Modul 3 • Go-Routines & Channel Concurrent CSP

Pengenalan Konsep Concurrent, Buffered Channel, Select & Mutex

Eksekusi fungsi di thread ringan goroutine (go worker()). Komunikasikan data antar-goroutine melalui unbuffered/buffered channel, multiplexing dengan select, serta lindungi shared memory dengan sync.Mutex agar bebas data race.

Modul 4 • Database Design RDBMS DDL & DML

Normalisasi Relasional, Advanced Query & Transaksi ACID

Mengeksplorasi skema database relasional (RDBMS) menggunakan DDL (CREATE TABLE, ALTER) dan DML (SELECT, INSERT, UPDATE). Kuasai integritas transaksi ACID dan Row-Level Locking (FOR UPDATE).

Topik: Pointers & Receivers

Kapan wajib menggunakan Pointer Receiver (func (w *Wallet)) dibanding Value Receiver?

Kunci Jawaban: Wajib pointer receiver jika method perlu mengubah field struct (mutasi state), atau jika struct berukuran besar sehingga pembuatan salinan memori (pass-by-value) tidak efisien. Jika menggunakan Mutex di dalam struct, pointer receiver mutlak agar mutex tidak tersalin.
Topik: Concurrency Channels

Apa perbedaan fatal antara Unbuffered Channel vs Buffered Channel?

Kunci Jawaban: Unbuffered channel memblokir pengirim sampai ada penerima yang siap (synchronous rendezvous). Jika tidak ada penerima, pengirim terkunci (deadlock hazard). Buffered channel memiliki kapasitas penampung, pengirim hanya memblokir jika buffer penuh.
Topik: Data Types & Invariants

Mengapa nilai uang mutlak TIDAK BOLEH disimpan sebagai float64?

Kunci Jawaban: Representasi biner IEEE-754 floating point memiliki ketidakpresisian pecahan (misal: 0.1 + 0.2 = 0.30000000000000004). Selalu simpan nominal uang dalam integer sen (int64) atau tipe SQL NUMERIC(18, 4).
Topik: RDBMS Locking

Apa fungsi SELECT ... FOR UPDATE pada database relasional?

Kunci Jawaban: Menerapkan Row-Level Lock eksklusif pada baris yang dibaca hingga transaksi selesai (COMMIT/ROLLBACK). Mencegah transaksi lain mengubah data saldo secara bersamaan, sehingga mencegah race condition overdraft.
Bootcamp Fase 2 • Arsitektur Web Microservices & Frameworks

Membuat Web Microservices Architecture dengan Framework Gin & Echo, PostgreSQL, dan k6

Go (Golang) Echo / Gin PostgreSQL k6 Grafana

Di fase ini siswa akan belajar membuat web microservices architecture dengan framework Gin & Echo, menerapkan concurrency patterns, dokumentasi Swagger, migrasi PostgreSQL, hingga pengujian performa API dengan tools k6 Grafana.

Modul 1 • Concurrency Pattern Worker Pool • Pipeline

Worker Pool, Fan-Out / Fan-In & Context Propagation

Mempelajari step konsep concurrency pattern. Membatasi alokasi goroutine aktif menggunakan Worker Pool agar tidak menenggelamkan database, serta menghubungkan context.WithTimeout untuk mencegah kebocoran goroutine (goroutine leak) saat klien HTTP memutus koneksi.

Modul 2 • Fundamental API Programming REST • Swagger • k6

RESTful Standards, Swagger OpenAPI & Pengujian Beban k6

Pengenalan API programming: implementasi REST API standar, dokumentasi otomatis dengan Swagger, serta pengujian performa dan ketahanan API (RPS & p95 latency) menggunakan tools modern bertenaga k6 Grafana.

Modul 3 • Database PostgreSQL Indexing • Migrations

Skema Enterprise, B-Tree Indexing & Tips Migrasi SQL

Mempelajari database PostgreSQL untuk skala produksi: penentuan indexing strategy yang efisien, manajemen connection pool, serta praktik terbaik versioning schema migrations SQL tanpa downtime.

Modul 4 • Web Server & Go Routing Echo / Gin • JWT Auth

Routing Handlers, Middleware Chaining & Token Security

Memahami Web Server dan Go Routing untuk membuat antarmuka API, mengamankan endpoint dengan otentikasi token (JWT Bearer Token), menerapkan middleware chain (Logger, CORS, Recover), hingga kesiapan deployment.

Topik: Worker Pool Pattern

Mengapa sistem high-traffic tidak boleh membuat goroutine tak terhingga (unbounded)?

Kunci Jawaban: Unbounded goroutines saat lonjakan traffic (traffic spike) akan menguras memory heap dan melipatgandakan koneksi ke database hingga melampaui pool limit (connection exhaustion). Worker Pool membatasi worker aktif ke angka terprediksi (misal: 20–50 worker).
Topik: k6 Load Testing

Apa metrik utama yang dievaluasi saat uji performa API dengan k6?

Kunci Jawaban: RPS (Requests Per Second) maksimum yang dapat ditangani, HTTP error rate (< 0.1%), dan ambang batas latensi p95/p99 (95% request harus selesai di bawah 200ms).
Topik: JWT Token Security

Bagaimana alur validasi token JWT di middleware Go?

Kunci Jawaban: Middleware membaca header Authorization: Bearer <token>, memverifikasi tanda tangan kriptografi (HMAC-SHA256) menggunakan secret key server, memeriksa tanggal kedaluwarsa (exp claim), lalu menyematkan user context ke request context.
Topik: PostgreSQL Migrations

Mengapa DDL schema migration wajib dipisah ke file up.sql dan down.sql?

Kunci Jawaban: Agar sistem CI/CD deployment memiliki kemampuan rollback otomatis (down.sql) secara aman jika rilis versi baru mengalami kegagalan, tanpa merusak konsistensi tabel yang sudah ada.
Bootcamp Fase 3 • Arsitektur Microservices Lanjutan & DevOps

Microservices gRPC, Database NoSQL, Serverless & Final Projek Real-Time

Go (Golang) gRPC / Protobuf SQL NoSQL (Redis)

Siswa akan mendalami konsep microservices, framework gRPC, Database NoSQL, serta cara mengukur performa web API dengan VPS, containerization Docker & Kubernetes, dan membuat final project real-time.

Modul 1 • Microservices & gRPC Protobuf • RPC Call

Protocol Buffers (.proto), Binary Serialization & Inter-Service RPC

Mempelajari konsep microservices terdistribusi dengan framework gRPC. Mendefinisikan kontrak data binary menggunakan Protocol Buffers (.proto) yang 7–10x lebih hemat bandwidth dan cepat dibanding representasi JSON teks pada REST HTTP.

Modul 2 • Database NoSQL Redis • Cache-Aside

Redis Key-Value, Strategi Cache-Aside & Cache Invalidation (TTL)

Memahami database NoSQL (Redis) untuk read-heavy optimization. Terapkan strategi Cache-Aside (Cek Cache → Fallback DB → Set Cache), kelola kedaluwarsa TTL, dan cegah insiden Cache Stampede / Thundering Herd saat traffic melonjak.

Modul 3 • Serverless & DevOps Docker • CI/CD • VPS

Docker Multi-Stage Build, CI/CD Pipeline & VPS Deployment

Mempelajari konsep containerization Docker multi-stage build (binary ramping < 25MB), orkestrasi Kubernetes dasar, pipeline otomatis CI/CD, antrean asinkron (Queue-ing / Caching), serta deployment ke VPS production Linux.

Modul 4 • Final Projek Real-Time WebSockets • SSE

Real-Time Data Streaming, WebSockets, & Server-Sent Events

Membuat web API production-ready dengan konsep real-time streaming menggunakan Server-Sent Events (SSE) atau WebSockets, sehingga status settlement transaksi bank atau notifikasi dapat diperbarui instan di antarmuka klien.

Klik untuk membuka kunci jawaban
Topik: gRPC vs REST

Mengapa komunikasi antar-microservices lebih disukai menggunakan gRPC dibanding REST JSON?

Kunci Jawaban: gRPC memanfaatkan Protocol Buffers biner yang jauh lebih ringkas daripada JSON teks, berjalan di atas HTTP/2 dengan multiplexing koneksi tunggal, serta memiliki type safety mutlak yang di-generate langsung dari file .proto.
Topik: Redis Caching Pattern

Apa itu fenomena Cache Stampede dan bagaimana cara memitigasinya?

Kunci Jawaban: Terjadi ketika kunci cache populer kedaluwarsa (expired), memicu ratusan request bersamaan membombardir database utama untuk re-fetch. Mitigasi: pasang Mutex Lock / Singleflight di level backend agar hanya satu goroutine yang melakukan query database.
Topik: Docker Multi-Stage

Mengapa Dockerfile untuk aplikasi Go wajib menggunakan Multi-Stage Build?

Kunci Jawaban: Stage builder menggunakan image besar dengan Go compiler. Stage final hanya menyalin binary hasil kompilasi ke base image minimal (scratch atau alpine), memangkas ukuran image dari ~800MB menjadi < 20MB dan meminimalkan celah keamanan OS.
Topik: Real-Time SSE vs WebSockets

Kapan Server-Sent Events (SSE) lebih tepat digunakan dibanding WebSockets?

Kunci Jawaban: SSE tepat digunakan saat komunikasi data hanya berjalan satu arah dari server ke klien (unidirectional streaming, misal: feed event transaksi atau status SSE). SSE berjalan di atas HTTP standar tanpa overhead protokol khusus dan memiliki fitur auto-reconnect bawaan di browser.
