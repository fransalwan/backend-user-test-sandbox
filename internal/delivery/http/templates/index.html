💰 Modul 0 • Hukum Utama Rekayasa Finansial Zero-Tolerance Rule

1. Mengapa Dilarang Keras Menggunakan Float/Double untuk Uang?

Format floating-point (standar IEEE 754) menggunakan aproksimasi biner base-2 yang tidak bisa merepresentasikan pecahan desimal basis 10 secara presisi mutlak.

// Contoh Bug Akurasi Float di Go:
var a float64 = 0.1
var b float64 = 0.2
fmt.Println(a + b) // Hasil: 0.30000000000000004 (Bocor 0.0000000000000004!)
✅ Standar Industri Perbankan & Fintech: Simpan nilai moneter dalam satuan terkecil (sen / cents) sebagai int64 di Go dan BIGINT di SQL. Contoh: $1.000,00 direpresentasikan murni sebagai angka bulat 100000 sen.

2. Prinsip Double-Entry Bookkeeping (Pembukuan Berpasangan)

Jangan pernah hanya mengupdate saldo secara naif (UPDATE wallets SET balance = balance - 100). Tanpa riwayat mutasi berpasangan, sistem audit gagal total. Saldo adalah akumulasi (sum) dari seluruh baris mutasi di tabel ledger_entries:

  • Immutable (Append-Only): Baris ledger dilarang di-UPDATE atau di-DELETE.
  • Zero-Sum Balance: Setiap pengeluaran (DEBIT) harus seimbang dengan penerimaan (CREDIT) di sisi akun lawan.

📋 Constraints & Spesifikasi Ujian: Ketik manual • Tanpa contekan instan
  • amount > 0 (nominal penarikan dalam sen / int64)
  • wallet.balance >= 0 (Invarian Moneter: DILARANG MINUS / OVERDRAFT!)
  • Wajib mengembalikan ErrInsufficientFunds jika saldo tidak mencukupi.
  • Uji Stres (Test Case 3): 50 goroutine menarik $25 serentak dari saldo $1.000 → Saldo akhir tepat $0.
Butuh Bantuan?
💡 Hint 1: Memahami Masalah Race Condition (Lost Update)

Operasi pengecekan saldo if w.balance < amount dan pemotongan saldo w.balance -= amount adalah dua langkah terpisah. Jika 50 goroutine membaca saldo pada saat bersamaan, semuanya akan melihat saldo mencukupi dan semuanya akan memotong saldo! Anda harus memastikan hanya satu goroutine yang boleh mengeksekusi blok kode ini sekaligus.

💡 Hint 2: Menambahkan Pengunci Mutex ke Struct

Go menyediakan primitif sinkronisasi memori bawaan yaitu sync.Mutex. Tambahkan field mu sync.Mutex ke dalam deklarasi type SharedWallet struct agar dompet memiliki kunci pengaman sendiri.

💡 Hint 3: Pola Penulisan Lock & Defer Unlock

Di awal fungsi DeductWallet, ketik w.mu.Lock(). Tepat di baris berikutnya, ketik defer w.mu.Unlock(). Menggunakan defer menjamin lock selalu dilepaskan meskipun fungsi Anda me-return error ErrInsufficientFunds di tengah jalan!

📄 Lembar Spesifikasi Proyek Take-Home (Junior Backend Engineer Challenge) Spesifikasi Dasar
1. Functional Requirements:
  • Endpoint POST /api/v1/transfers (sender_id, recipient_id, amount_cents, idempotency_key).
  • Wajib menggunakan ACID Database Transaction (BEGIN ... COMMIT/ROLLBACK) agar saldo tidak hilang jika server crash di tengah mutasi.
  • Validasi input mendasar: saldo pengirim mencukupi, nominal > 0, dan pengirim tidak boleh transfer ke diri sendiri.
2. Code Quality & Standards:
  • Bahasa: Golang dengan struktur modular rapi (Handler, Service, Repository).
  • Format Uang: Tipe data integer murni int64 sen (Dilarang menggunakan float).
  • Unit Test untuk logika bisnis mutasi saldo dompet.
  • Sertakan README.md panduan run lokal dan Dockerfile / compose.
