🏛️ 4 Invarian Finansial yang Wajib Dikuasai

✕ Mengapa Dilarang Pakai Float?

Komputer merepresentasikan floating-point secara biner IEEE 754 (0.1 + 0.2 = 0.30000000000000004). Di bank, ini menimbulkan selisih pembulatan sen (*fractional pennies*). Solusi: Selalu gunakan int64 (sen) atau tipe exact decimal.

✓ Double-Entry Bookkeeping

Setiap perpindahan uang wajib menghasilkan dua mutasi berpasangan yang seimbang (DEBIT dan CREDIT). Tabel mutasi bersifat immutable (hanya boleh INSERT, dilarang UPDATE/DELETE).

✓ Idempotency Key Lifecycle

Klien mengirim header Idempotency-Key: UUID. Transaksi dikunci saat PROCESSING. Jika request duplikat datang bersamaan ➡️ return 409 Conflict. Jika sudah COMPLETED ➡️ sajikan cached response.

✓ Saga vs Two-Phase Commit (2PC)

2PC memegang lock database antar sistem dan rentan deadlock jika gateway pihak ketiga lambat. Saga membagi transaksi menjadi langkah independen dan mengandalkan Compensating Transaction (Refund) jika langkah lanjutan gagal.

💼 Pertanyaan Wawancara Tech Lead Fintech

Q: Kapan memilih Pessimistic Locking dibanding Optimistic Locking?
A: Pilih Pessimistic pada kasus high-contention (seperti saldo dompet, kuota flash sale) agar tidak terjadi retry storm. Pilih Optimistic pada low-contention (seperti edit profil pengguna).

Q: Bagaimana cara mencegah Deadlock saat Alice mentransfer ke Bob dan Bob mentransfer ke Alice bersamaan?
A: Selalu terapkan Lock Ordering: Urutkan kunci berdasarkan ID terkecil terlebih dahulu (SELECT ... WHERE id IN (A, B) ORDER BY id FOR UPDATE).
